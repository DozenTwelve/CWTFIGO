# Windows

- Before a feature update or after a bad monthly one: Windows release health, https://learn.microsoft.com/en-us/windows/release-health/. Known issues per version, with status, workarounds, and whether a Known Issue Rollback already undid the change.
- Monthly updates: Patch Tuesday (second Tuesday) carries the security fixes. The optional non-security preview later in the month only installs when the user picks it or turns on "Get the latest updates as soon as they're available"; its fixes reach everyone in the next Patch Tuesday. A machine that has the preview is ahead of the documented baseline.
- Windows 11 still writes "Windows 10" into `ProductName` under `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion`. Build decides: `CurrentBuild` 22000 or higher is Windows 11. `DisplayVersion` (e.g. 23H2) in the same key and `Win32_OperatingSystem.Caption` are right; `ReleaseId` stopped at 2009.
- winget has two sources, `winget` (community manifests, github.com/microsoft/winget-pkgs) and `msstore`: `winget source list`. `winget list` and `winget upgrade` cover programs installed any way, not only by winget, so an upgrade can replace a vendor's own updater's version. Hold one with `winget pin add <id>`.
- Windows Update ships drivers too and can replace a vendor driver installed by hand (GPU, Wi-Fi, audio). Policy to stop it: `ExcludeWUDriversInQualityUpdate` = 1 under `HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate`. After a driver regression, check update history for a driver entry first.
- Removing a monthly update: Settings, Update history, Uninstall updates. `wusa /uninstall` doesn't work on combined servicing stack and cumulative packages; `DISM /Online /Get-Packages` then `/Remove-Package`.
- Ways back, not cleanup: `C:\Windows.old` is what Settings, Recovery, "Go back" uses for 10 days after a feature update; Disk Cleanup's "Previous Windows installation(s)" deletes it. Restore points (`rstrui`) exist only if System Protection is on for the drive, often off by default. Ask before removing either.
- Over SSH into Windows' own OpenSSH Server, a client from OpenSSH 10.1 on (Git Bash ships one) prints a few lines on stderr on every connection: the server doesn't offer a post-quantum key exchange. Harmless for the session and not part of the script's output. It's a security notice, so leave it on unless the owner wants it quiet: then `WarnWeakCrypto no` under that host in `~/.ssh/config` (older clients reject the option, so per host only).
- Installing OpenSSH Server: `Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0` fails in pwsh 7 with `Class not registered`. Run it in Windows PowerShell 5.1, or `dism /Online /Add-Capability /CapabilityName:OpenSSH.Server~~~~0.0.1.0`, both elevated.
- Keys for an account in Administrators: the stock `sshd_config` ends in `Match Group administrators`, so sshd reads only `C:\ProgramData\ssh\administrators_authorized_keys`, never `~\.ssh\authorized_keys`. `ssh-copy-id` doesn't help (wrong file, and it runs sh on the far side). Append the key there in an admin PowerShell; sshd ignores the file unless only Administrators and SYSTEM have access: `icacls.exe <file> /inheritance:r /grant '*S-1-5-32-544:F' /grant '*S-1-5-18:F'` (SIDs, so a Chinese or other localized Windows doesn't trip over group names). A refused key shows in `Get-WinEvent -LogName 'OpenSSH/Operational'` (no admin needed) as `Connection closed by authenticating user ... [preauth]`.
- A `~/.ssh/config` copied from a Mac: Windows' ssh and Git Bash's don't know `UseKeychain` and exit with `Bad configuration option`. Remove those lines, or put `IgnoreUnknown UseKeychain` at the top.
- Input trouble after an upgrade batch, IME typing only ASCII (Weasel/Rime passing keys through), the cursor vanishing: check for a stuck key before restarting anything. Sample `GetAsyncKeyState` for every VK a few times while nobody touches the keyboard; once it was Caps Lock (VK 0x14) held in 5 of 5 samples, and one press and release fixed both. Suspected, unconfirmed: Logitech G HUB reinstalling its virtual keyboard during the batch.
- An Epic Games Launcher upgrade (1.3.93 to 1.3.210) silently installed Microsoft GameInput, with services `GameInputRedistService` and `GameInputSvc`. A suspect for input problems after an upgrade batch; stopping `GameInputSvc` didn't change the one seen.
- LM Studio re-downloads any engine kind that's missing. Deleting old llama.cpp backend folders works only for older versions within a kind; removing a whole kind (avx2, cuda-avx2, vulkan) makes it fetch its default pack again (about 670M).
- `python3` on Windows is usually the Microsoft Store alias (`%LOCALAPPDATA%\Microsoft\WindowsApps\python3.exe`): it runs nothing, even with Python installed. cw's `pyfind` skips it; tools that call `python3` directly (other plugins, scripts) silently do nothing. Settings, Apps, App execution aliases turns it off.

## Pitfalls

- UserAssist (last-run times under `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\UserAssist`) stays empty when `Start_TrackProgs` = 0 under `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced` (Settings, Privacy, "Let Windows track app launches"). Read that value before writing a decoder.
- `Get-ChildItem "Registry::HKEY_CLASSES_ROOT\*\shell"` treats `*` as a wildcard and walks all of HKCR (ran past 120 s). Use `-LiteralPath` for the `*` key.
- `reg query HKLM\SOFTWARE /s /f <string>` takes minutes per string. Read the known keys for the app (`references.md`, uninstall keys, the vendor key) instead of searching the hive.
- `Microsoft-Windows-Kernel-PnP/Configuration` logs driver installs, not replugs, so it can't date a device dropping out. Poll `Get-PnpDevice -PresentOnly` over time instead.
