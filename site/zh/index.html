Claude, what the fuck is going on?

喊 Claude 的名字。它找出哪里不对，你点头才修，还会记住。

一行一行粘贴到 Claude Code
/plugin marketplace add DozenTwelve/CWTFIGO/plugin install cwtfigo@cwtfigo

然后运行 /reload-plugins（或重启 Claude Code），再输入 cwtfigo。它提出给这台电脑做个体检，就说明装好了。

怎么用

喊它的名字

输入“CWTFIGO”，再说哪里不对。或者只输入“cwtfigo”，它会提出做个体检。

先问你

插件自带的只读检查，同意一次就都能跑。Claude 给你的机器写的每个脚本，第一次运行前都会问你，脚本变了会再问。会改动电脑的事，每次都问。

它记得

笔记留在你的电脑上，一台机器一个文件夹，经 SSH 连到的其他机器也一样。下次从这里接着来。

之后不用 AI

Claude 给每台机器写好它自己的体检和保养脚本。一个小菜单不经过 Claude 也能跑它们，支持 Mac 和 Linux。

常见问题

需要装什么？

Claude Code、git 和 python3，后者用来搜过去的修法。Mac 上用 xcode-select --install 装 git。Windows 上它跑在 Git Bash 里，反正 Claude Code 在那边也要它。第一次用 Opus 效果最好：/model opus。

怎么更新？

Claude Code 不会自己更新这个插件：它只自动更新 Anthropic 自己的插件市场。要现在更新，运行 /plugin，打开 Marketplaces 标签页，选 cwtfigo，选 Update marketplace，再运行 /reload-plugins。在同一个地方选 Enable auto-update，以后每次 Claude Code 启动时都会自己更新。

怎么卸载？

在 Claude Code 里，/plugin marketplace remove cwtfigo 会连同插件市场一起卸掉插件。在终端里，rm -rf ~/.local/bin/cwtfigo "${XDG_RUNTIME_DIR:-$HOME/.cache}/cwtfigo-visit" 删掉菜单和它记录过往访问的小标记。如果你为菜单加过 PATH 那一行，把它删掉；装过 Hermes 的话，照 HERMES.md 说的去掉。你的笔记还在 ~/.cwtfigo：只有想彻底删掉时才删这个文件夹。

能管哪些电脑？

Mac、Linux、Windows、Steam Deck 和路由器：你面前这台，或者同一网络里经 SSH 连到的其他机器。你的笔记本可以照看服务器、NAS 和路由器，所有机器的笔记放在一处。在 macOS、Windows、Arch、Debian 及其衍生版（Ubuntu、Mint、Pop!_OS、Raspberry Pi OS 等）和 OpenWrt 路由器上，体检和保养从现成的脚本起步。其他系统，比如 Fedora 或 Steam Deck，也能用，只是 Claude 给它们写脚本时起点少一些。

为什么不直接问 Claude？

没有笔记，每次对话都从零开始：这台机器是什么、上个月试过什么。CWTFIGO 记得。每台机器还有自己的体检和保养脚本，由 Claude 为这台机器写、你点头同意，之后每次都重跑，学到新东西就改写。

不用 AI 能用吗？

能，Mac 和 Linux 上。终端里有个小菜单，按机器列出 Claude 写好、你同意过的脚本，直接就能跑；所以第一天它是空的，用得越多越满。在 Claude Code 里说“CWTFIGO install the TUI”，然后在终端里输入 cwtfigo。

笔记存在哪儿？

存在 ~/.cwtfigo，你电脑上的一个 git 文件夹。删掉它就没了。几台电脑可以通过你自己的私有 git 远端共用这些笔记，绝不用公开的。

Claude 能看到什么？

它读到的内容（名字、路径、端口、日志行）会经过 Anthropic，和你给 Claude Code 看的其他东西一样。清理时它只量大小，从不看文件内容。

它会动我没让它动的东西吗？

只有你喊它名字时它才开始。不带名字描述问题，你得到的是普通的 Claude 回答。你没指给它的机器，它从不碰。

出问题了怎么办？

告诉它“CWTFIGO，刚才那个没用”，或者“CWTFIGO，就这个开个 issue”。它会起草一份 bug 报告，写上版本和经过，先给你看，你点头才用你的 GitHub 账号发出去。发出去需要装好 GitHub 的 gh 工具并登录（gh auth login）。也可以自己开一个。安全问题见 SECURITY.md。

它会让 Claude 变聪明吗？

不会，也不会让它变笨。效果很大程度上取决于模型。修不好的问题先搁置、拿出证据、脚本先试运行不真改，这些都来自 skill 里的规则，不是代码，所以要靠模型去遵守。帮朋友的笔记本修一次，用普通的 Claude Code 就够了。你每周都要照看的机器，用得越久它越好用。
