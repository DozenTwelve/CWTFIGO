Claude, what the fuck is going on?

一个 Claude Code 插件：修你的机器，并把一切记下来。

粘贴到 Claude Code
/plugin marketplace add DozenTwelve/CWTFIGO/plugin install cwtfigo@cwtfigo
从克隆安装

叫它的名字，然后看着。

句子里出现 “CWTFIGO”、“what the fuck is going on” 或 “一体どうなってやがるんだ” 它才会醒。不叫名字只描述问题，你得到的是普通回答。

每个结论都附上它依据的输出。

你不点头，它什么都不读。

第一次访问只弄清这是台什么机器。之后每一种新的读取都先问你，每个脚本按哈希批准一次。改一个字节，它就再问一次。

它读到的内容会经过你的模型提供方。它会直说。

长通，绕过，或停下。

问题碰上石头，就像树根碰上石头。CWTFIGO 告诉你是哪一种。

我们分析过的公开 bug 帖，最后的结局
修好45%真实的触发条件走过一遍之后才算。
绕过24%危害没了，原因还在，记录里写明。
停下26%没用的改动复原；问题记为搁置，写明何时再看。

每次访问都比上次便宜。

它学到的都写进 ~/.cwtfigo，你这边的一个私有 git 仓库：每台机器是什么、哪些不能碰、它的脚本、试过什么。你的几台操作机可以经一个私有远端共用它。删掉这个目录，记录就没了。

一份记录，管下面这些，本机或经 SSH。被修的机器上什么都不装。
记录里叫是什么怎么连

studioMac mini，macOSSSH
denWindows 11 台式机SSH
couchSteam DeckSSH

比 Claude 新的事，它现场去查。

训练停在某一天，你的软件包不会。CWTFIGO 带着原样的报错去出问题项目的上游 tracker 现场搜。

常见问题

我的数据去哪儿？

记录留在你机器上的 ~/.cwtfigo，加上你自己配的私有远端（如果有）。访问中读到的内容会经过你的模型提供方，Claude Code 里的一切都是这样。它替你起草给上游的 bug 报告，要你点头才发，名字、IP、路径都会抹掉。

需要装什么？

git，搜索还要 python3。Mac 上就是 Command Line Tools：xcode-select --install。Windows 上它跑在 Git Bash 里，反正 Claude Code 在那边也要它。

能让它别老问吗？

它本来就越问越少：你同意过一次的读取，之后不再问，只有改动才问。想 12 小时内连剩下的也不问，就让 Claude 打开 YOLO；只有你能打开，说“YOLO off”就提前结束。删数据、动分区、任何可能把 SSH 锁在外面的事，照样要你打 yes。

不用 AI 能用吗？

Mac 和 Linux 上可以：cwtfigo 是终端里的一个小菜单，跑你已经同意过的脚本，不经过模型。在 Claude Code 里说“CWTFIGO install the TUI”就装好。没有 Windows 版。

修不好怎么办？

它会直说，把没帮上忙的改动复原，把问题搁置，并写下什么情况值得再看：某个包的新版本、上游 issue 关闭、零件到货。

要 sudo 的事呢？

给你一条命令，在你自己的终端里跑，sudo 在那里问你密码。它永远看不到密码。

把它指向坏掉的那台。

粘贴到 Claude Code
/plugin marketplace add DozenTwelve/CWTFIGO/plugin install cwtfigo@cwtfigo
